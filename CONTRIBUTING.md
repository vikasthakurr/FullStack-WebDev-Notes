# Contributing to Full-Stack Web Dev Notes

Thanks for your interest in contributing! Here's how you can help.

## How to Contribute

### 1. Fix Errors or Typos

- Fork the repo
- Fix the issue in the relevant `.md` file
- Submit a PR with a clear description of what you fixed

### 2. Improve Existing Notes

- Add better code examples
- Add diagrams (Mermaid syntax preferred)
- Clarify confusing explanations
- Update outdated information

### 3. Add New Notes

If you want to add a new topic:

1. Check if it fits within an existing module
2. Follow the established note format (see below)
3. Add the file with proper numbering (`XX-topic-name.md`)
4. Update the README table of contents

## Note Format

Every note should follow this structure:

```markdown
# Topic Title

## What Is [Topic]?

Clear explanation with an analogy for complex concepts.

## Why It Matters

Practical importance — why should a developer care?

## Core Content

- Clear headings for sub-topics
- Code examples (working, copy-pasteable)
- Mermaid diagrams where helpful
- Comparison tables where relevant

## Best Practices

Numbered or bulleted actionable recommendations.

## Common Mistakes

| Mistake | Why It's Wrong | Fix |
| ------- | -------------- | --- |
| ...     | ...            | ... |

## Summary

- Bullet points summarizing key takeaways
- 5-8 points maximum
```

## Style Guidelines

- Use **clear, simple English** — avoid jargon without explanation
- Code examples should be **complete and runnable**
- Use **JavaScript/TypeScript** for all code examples
- Prefer **practical examples** over abstract ones
- Add **analogies** for complex concepts
- Keep explanations **concise** — every sentence should add value
- Use Mermaid for diagrams (GitHub renders them natively)

## Code Examples

- Use modern syntax (ES6+, async/await)
- Add comments explaining non-obvious lines
- Show both ❌ wrong and ✅ correct approaches
- Keep examples focused — don't combine too many concepts

## Pull Request Process

1. Fork the repository
2. Create a feature branch (`git checkout -b add-websocket-note`)
3. Make your changes
4. Ensure markdown renders correctly (preview on GitHub)
5. Submit a PR with:
   - What you added/changed
   - Why (if it's not obvious)

## What NOT to Contribute

- Notes that just copy documentation verbatim
- AI-generated content without review/verification
- Content unrelated to full-stack web development
- Notes in languages other than English

## Questions?

Open an issue if you're unsure about something before starting work.
